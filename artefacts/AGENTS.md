# Rules for working in `artefacts/`

These apply when filling in or editing the numbered artefacts. Templates are filled in place, in the project workspace.

## Filling in a template

- Keep every section. If something does not apply, write `not applicable` and the reason.
- Label each claim `evidence` with its source (for example `evidence: kick-off notes, 12 May`) or `gap`. A section with no gaps is suspicious. Say so.
- Draft only from material the owner has given you. Do not invent quotes, metrics, research or stakeholder positions.
- Use roles, never personal names. Use placeholders such as `[Client]`.
- Read `project.config.md` for the accessibility level, data classes and stakeholders. Do not repeat its contents here, link to it.
- Finish with the "Done when" checklist. Tick only what is true, and list what is not.
- Set `Status` to `draft` until the owner has reviewed it, then `reviewed`.

## Core and optional

Core five: `00`, `01`, `02`, `03`, `10`. The rest are added when the project needs them (see the README, step 5).

## Examples

`artefacts/examples/` holds fictional, filled-in examples. They show the level of detail and tone. Read one only when asked, and never copy its content into a real project.
