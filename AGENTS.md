# AGENTS.md

Index and ground rules for any AI agent working in this repo. Keep this file short: detail lives in the files it points to.

## What this repo is

A **private project workspace** for UX and product design work, created from a public template. It holds the written context (artefacts), decisions and drafts for one project. It is not the client's codebase and nothing here is pushed to the client's repo.

The owner is a senior UX/product designer working on public sector and B2B projects. Accessibility, security and many stakeholders are the norm, not the exception.

## Start of every task

1. Read `project.config.md`. It sets the accessibility level, data classes, languages and stakeholders.
2. Read only the artefacts in `artefacts/` that the task needs. Do not load them all.
3. If a fact you need is missing, say so and ask. Never fill a gap with a guess.

## How to work with me

- I decide. You draft, check and explain. Propose, do not impose.
- Explain what you did and why, in plain language.
- If there is more than one reasonable approach, name them and let me choose.
- Check named paths first. Do not search the whole repo when you know where to look.
- Keep changes small and focused on what I asked.

## Hard rules

- **No claims without evidence.** Never write "accessible", "compliant", "secure", "tested" or "validated" about a design. Report each check as `pass`, `fail` or `cannot tell from a design`.
- **Label every claim** as `evidence` (with its source) or `gap`. Do not invent user quotes, research findings, metrics or stakeholder positions.
- **No client data.** No real names, personal data, confidential figures or screenshots in prompts, files or commits. Use placeholders such as `[Client]`, `[Stakeholder A]`.
- **No secrets.** Never write keys, tokens or passwords to the repo. Use `.env.example` with empty values.
- **Do not replace real people.** User testing, testing with users who have access needs, security review and legal advice need humans. Say so when relevant.
- **Legal-adjacent output** ends with: "Design-stage review, not an audit or conformance statement. Check legal duties with a qualified adviser."
- **Decisions are recorded by role**, not by personal name, in `artefacts/10-decision-log.md`.

## Design work

- Design against the written context, not your defaults. Read the design system rules and examples before producing UI.
- Use design tokens by name. No raw hex values or arbitrary pixel values where a token exists.
- After a draft, list which choices were left at default and ask whether each was a decision. Do this as a review, not as a restriction while generating.

## Where things are

- `project.config.md`: project facts. Read first.
- `docs/ai-workflow.md`: roles, workflow, session habits. Human-facing, read only when asked.
- `docs/important-notes.md`: planning notes and decisions for the template itself.
- `artefacts/`: spec templates and the filled-in project documents.
- `design-system/`: tokens, rules and annotated examples. Read before producing UI.
- `.claude/skills/`: skills, loaded when a task matches their description.

Files listed in the README but not present yet are planned. Do not assume they exist.

## Session and commit habits

- Suggest `/clear` when the task changes and `/compact` when a long session slows down.
- Do not edit this file mid-session unless I ask.
- Commit after each finished subtask with a clear message. Do not push to any branch I have not named.
- If a check or hook fails, fix the cause. Do not skip or disable it.
